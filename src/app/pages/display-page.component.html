Display and editing

Use these inputs when the editor is already working and you want to tune how it feels inside your UI. Display inputs affect what the user sees. Editing inputs affect how text is entered, indented, and selected.

  • Display inputs control visible editor chrome: [lineNumbers] adds the left line-number gutter, [lineWrapping] wraps long lines inside the editor, and [highlightActiveLine] marks the line where the cursor is.
  • Whitespace inputs make invisible characters visible: [highlightWhitespace] marks spaces and tabs, while [highlightTrailingWhitespace] marks extra spaces at the end of a line.
  • Editing inputs control concrete typing behavior: [tabSize] changes tab width, [indentUnit] defines one indentation step, and [multipleSelections] allows more than one cursor or selected range.

Display and editing inputs

Long lines in narrow layouts

Configured with [lineWrapping]="true", [lineNumbers]="true", [highlightActiveLine]="true", [scrollPastEnd]="true", and a [placeholder]. Try it Resize the page or place the cursor on the long string. The line wraps inside the editor instead of forcing horizontal scrolling, and the active line is highlighted while you edit.

Whitespace review

Configured with [highlightWhitespace]="true", [highlightTrailingWhitespace]="true", and [lineNumbers]="true". Try it Look at the spaces inside the function body and after const name = 'Angular';. CodeMirror marks whitespace so formatting mistakes are visible before users save or copy code.

Indentation and selections

Configured with [tabSize]="2", [indentUnit]="' '", [indentOnInput]="true", [multipleSelections]="true", and [drawSelection]="true". Try it Put the cursor inside the object, press Enter, and CodeMirror indents the new line with two spaces. Type a closing } on an indented line to see [indentOnInput] align it. Multiple selections are enabled and drawn by CodeMirror; use the Commands tab for buttons that create extra cursors programmatically.
